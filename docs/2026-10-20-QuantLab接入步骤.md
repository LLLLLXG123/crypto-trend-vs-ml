# 把策略接入 QuantLab：部署和操作步骤

平台：github.com/NagisaShip/quantlab（v0.1.0-preview.1，自己部署在本机）。
下面每一步都在本机 WSL 里实测过（10-20 晚上）。实测用的是临时目录，你自己部署时按这里的路径来。

## 一、能放进去什么

| 策略 | 能不能放 | 怎么放 |
|---|---|---|
| 论文原版 TrendEnsemble | 能 | 改写成平台的 Python 写法：`quantlab/TrendEnsemble_quantlab.py` |
| 调参版 TrendTuned | 能 | 同一份代码换参数：`quantlab/TrendTuned_quantlab.py` |
| 机器学习 MLXGBoost | 不能直接放 | 平台不允许策略 import xgboost / freqtrade（FreqAI），见第八节 |

为什么不用平台的“导入 Freqtrade”：导入器不支持 `adjust_trade_position`（我们每天调仓靠它），也不支持
`self.wallets`，会直接报错。所以改用平台自己的 `order_target_percent` 写法，规则一条没改。

## 二、部署（WSL，第一次约 10 分钟）

在 WSL 终端里依次执行：

```bash
cd ~
git clone https://github.com/NagisaShip/quantlab.git
cd quantlab

# Python 依赖（WSL 自带的 python3 没有 venv 模块，用 uv 建环境）
uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install -r requirements-dev.lock
uv pip install --no-deps -e .

# 前端（WSL 里已有 Node 24）
cd web && npm ci && npm run build && cd ..

# 建库
qagent migrate
```

启动（以后每次用平台只需要这三行）：

```bash
cd ~/quantlab && source .venv/bin/activate
export QAGENT_SANDBOX_MEMORY_MB=4096
qagent serve --with-worker
```

- 看到 `Uvicorn running on http://127.0.0.1:8000` 就好了，在 Windows 浏览器打开 http://127.0.0.1:8000 。
- 终端别关，关了平台就停了。
- 停止：在运行 `qagent serve` 的那个终端按一次 Ctrl+C，后台 worker 会跟着停。窗口已经关了或者按了没反应，
  就在任意 WSL 终端执行 `pkill -f quant_agent`，再用 `pgrep -af quant_agent` 确认没有输出。
  不要用 `wsl --shutdown`，它会把整个 WSL 关掉，包括在 WSL 里运行的 Claude Code。
- 日志一直在刷是正常的：平台每 5 分钟检测一次交易所连通性，纸面模拟运行时每 30 秒查一次价格。
- **`QAGENT_SANDBOX_MEMORY_MB=4096` 必须加**。平台默认给策略进程 1.5 GB 内存上限，这台电脑 32 核，
  numpy 按核数预留内存，超了上限，回测会报 `MemoryError`。实测加上这行就好了。
- 数据存在 `~/.quant_agent/`（数据库、行情缓存、策略）。

## 三、注册

1. 打开 http://127.0.0.1:8000 ，点注册，填用户名和密码（至少 8 位）。
2. 第一个注册的账号自动是管理员，不需要邀请码。
3. 第一次登录会弹出新手引导，可以跳过。

大模型密钥（AI 研究室用）不用配，不影响回测和模拟。

## 四、放策略

左侧「我的策略」→「新建策略」→ 选「空白策略」模板：

| 项 | 填 |
|---|---|
| 策略名称 | 论文原版（第二个策略填“调参版”） |
| 周期 | 1d |
| 标的池 | BTC/USDT,ETH/USDT |

进入编辑器后，把模板代码全删掉，粘贴 `E:\python code\bitcoin\quantlab\TrendEnsemble_quantlab.py` 的全部内容，
Ctrl+S 保存。调参版同样操作，粘贴 `TrendTuned_quantlab.py`。

保存后在编辑器的参数页能看到 PARAMS 里的 8 个参数，可以直接改着试。

## 六、要跑的几组回测

| 组 | 开始 | 结束 | 用来说明 |
|---|---|---|---|
| 全区间 | 2019-05-01 | 2026-10-19 | 平台结果和 Freqtrade 对得上 |
| 样本内 | 2019-05-01 | 2025-03-15 | 论文样本期 / 调参用的数据 |
| 样本外 | 2025-03-15 | 2026-10-19 | 论文发表后 / 调参没见过的数据 |
| 成本加倍 | 2019-05-01 | 2026-10-19 | 「手续费 %」改成 0.30，看手续费翻倍还赚不赚 |

两个策略各跑前三组。实测结果（手续费 0.15%，滑点和价差 0）：

| | 平台 | Freqtrade（PPT 里的数） |
|---|---|---|
| 论文原版 全区间 总收益 / 年化 / 最大回撤 / 夏普 | +198% / 15.7% / −15.8% / 1.19 | +204% / 16.0% / −16.8% / 1.21 |
| 论文原版 交易笔数 | 148 | 150 |
| 论文原版 样本内 → 样本外 年化 | 19.5% → 2.7% | 19.8% → 3.1% |
| 调参版 全区间 总收益 / 年化 / 最大回撤 / 夏普 | +790% / 34.0% / −24.8% / 1.33 | +770% / 33.6% / −24.7% / 1.32 |
| 调参版 交易笔数 | 161 | 162 |
| 调参版 样本内 → 样本外 年化 | 42.6% → 6.3% | 42.2% → 6.4% |
| 调参版 样本外最大回撤 | −24.8% | −24.7% |
| 手续费翻倍（0.30%）后全区间年化：论文原版 / 调参版 | 14.9% / 31.5% | — |

差一点是正常的：平台在收盘决策时按收盘价估算仓位，Freqtrade 在下一根开盘时按开盘价估算；
分段回测时平台每段都从 10000 现金重新开始，Freqtrade 的分段数字是从全区间曲线上截出来的。
结论完全一样：论文原版发表后超额收益没了；调参版样本内很漂亮，样本外只剩 6%，回撤超过 20% 的上限。

## 七、回测详情里的审查卡怎么读

平台每次回测会自动出一张审查卡，我们的两个策略都是“证据不足”，没有阻断项。逐条说明：

| 审查项 | 平台说 | 怎么回应 |
|---|---|---|
| 基准比较 | 没跑赢买入持有 BTC | 买入持有是满仓，我们平均只有两成左右仓位；公平的比法是“同等仓位持有”，PPT 里已经做了 |
| 没有任何止损 | 代码里没调 set_stop_loss | 止损在信号里：每个子信号的通道止损只升不降，收盘跌破就平。平台只认它自己的止损函数 |
| 成本压力 | 没附成本扫描 | 跑“成本加倍”那组；PPT 里还有 Freqtrade 的手续费敏感性 |
| 样本外验证 | 没附 holdout | 跑样本内 / 样本外两组 |
| 多重检验 | 不知道试了多少次 | 论文原版参数照抄论文，没试；调参版试了 500 组，样本外塌了正好说明这个问题 |
| 前视偏差 | 需要人工复核 | 平台的 history 只给已收盘数据；Freqtrade 的 lookahead-analysis 也没发现偏差 |

## 八、纸面模拟（用实时行情跑起来）

1. 打开策略编辑器，点右上角「批准版本」。平台规定只有批准过的版本能进模拟，改了代码要重新批准。
2. 左侧「纸面模拟」→「启动新实验」：策略选刚批准的那个，成交方式“平台撮合（纸面模拟）”，
   行情“真实行情”，交易所 OKX，虚拟资金 10000，手续费 0.15，滑点 0 → 「启动实验」。
3. 状态变成“运行中”，日志里有“已加载 … 根历史 bar 用于预热”。

要知道的：

- 日线策略每天只决策一次，在日线收盘后，也就是**北京时间每天早上 8 点**。启动后要等到第二天 8 点才有第一笔成交。
  所以想在 10-22 展示时有成交，**最晚 10-21 早上 8 点前启动**。
- 实测按 10-18 的行情，论文原版会买入约 11% 资金的 BTC 和 5% 的 ETH；调参版会买约 31% 的 BTC，ETH 不买。
- 平台的实时模拟启动时只加载最近 300 根 K 线。调参版最长回看 180 天，没影响；论文原版最长回看 360 天，
  前两个月少一个子信号（9 个里少 1 个），仓位会略低于回测。展示时如实说就行，也可以只用调参版做实时演示。
- 平台进程停了，实验也会停；重新启动平台后会从检查点接着跑（策略里写了 snapshot / restore）。
  但停机期间收盘的 K 线**不补下单**，所以每天早上 8 点那一刻，平台和电脑都要开着（电脑不能睡眠），不然那一天就跳过了。
- 网页上的「一键停止」会按最新价把模拟持仓全部卖掉并结束实验，结束后不能再继续，只能重新启动一个新实验。

## 九、交易所模拟盘（可选）

需要 OKX 模拟盘的 API 密钥（OKX 网页切到“模拟交易”→ API 创建，权限只勾读取和交易，要设 Passphrase）。

1. 左侧「交易所模拟盘」→ 选 OKX 模拟盘 → 填 Key、Secret、Passphrase。平台查一次余额，查得到才保存。
2. 「纸面模拟」→「启动新实验」→ 成交方式选“交易所模拟盘”→ 选刚才的连接，设单笔上限和当日亏损熔断 → 启动。

和纸面模拟的区别：成交价、手续费由 OKX 模拟盘撮合，能看出滑点。密钥只在平台里填，不要发给别人，也不要写进项目文件。

## 十、机器学习策略为什么不放

- 平台的策略沙箱只允许 import math、numpy、pandas 等纯计算库，xgboost、freqtrade（FreqAI）都不让用。
- 平台有自己的「预测模型」（梯度提升树等）和 `predict()`，但特征、训练窗口、目标都得重做，结果就不是
  我们那个模型了，两天内做出来也说不清和 Freqtrade 版的关系。
- 展示时可以这样讲：两个规则策略放到了第二个平台上，结果和 Freqtrade 对得上；机器学习策略依赖 FreqAI，
  留在 Freqtrade 里，结论不受影响（扣费后本来就是亏的）。

## 十一、常见问题

| 现象 | 原因 | 办法 |
|---|---|---|
| 回测报 `MemoryError` | 没设内存上限 | 启动前 `export QAGENT_SANDBOX_MEMORY_MB=4096` |
| 拉不到行情、报“未接入数据” | WSL 里设了代理环境变量，但代理软件没开 | 先 `unset HTTPS_PROXY HTTP_PROXY https_proxy http_proxy` 再启动；本机直连 OKX 是通的 |
| 数据是 Binance 的 | 交易所没改 | 运行设置里「交易所」选 OKX |
| 纸面模拟下拉框里没有策略 | 没批准 | 编辑器右上角「批准版本」 |
| 8000 端口被占 | 别的程序在用 | `qagent serve --with-worker --port 8001`，浏览器开 8001 |
| 改了代码后不能启动模拟 | 改代码会生成新版本 | 重新「批准版本」 |
