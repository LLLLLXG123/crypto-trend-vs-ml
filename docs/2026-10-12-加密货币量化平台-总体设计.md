# 加密货币量化交易平台 · 总体设计

- 状态：设计完成，用户已审阅通过（10-12）；阶段 1 实现计划已写好，待开始实现
- 更新：2026-10-12

## 1. 定位

- 用途：课程作品集。实盘是可选的最后一步，不追求长期无人值守。
- 核心产出：同一个策略分别跑「历史回测」和「OKX 模拟盘」，分析两者的偏差。

## 2. 已确定的需求

| 项     | 决定                                                |
| ----- | ------------------------------------------------- |
| 交易所   | OKX（模拟盘用 OKX 官方 Demo Trading）                     |
| 品种    | BTC-USDT、ETH-USDT 现货 + 对应的 USDT 永续合约，以后加币种只改配置    |
| 频率    | 1 小时 K 线                                          |
| 杠杆    | 合约最高 3 倍，逐仓模式                                     |
| 语言/环境 | 本地 Python 3.11（conda 环境 `bitcoin`）；服务器 Python 3.12（venv，见 7.5）                    |
| 研究与回测 | 主要在本地电脑跑；网站的回测实验室在服务器上跑（限流）                                            |
| 模拟盘运行 | 阿里云 2vCPU / 2GiB / 40G ESSD / 3M，**地域必须选中国香港或海外** |

| 展示网站  | FastAPI 后端 + 纯 HTML/CSS/JS 前端，部署在服务器；UI 风格按用户喜好实时迭代 |

## 3. 成功标准

1. 能从 OKX 拉取历史和实时行情，存到本地。
2. 至少一个策略能用**同一份代码**分别跑回测和 OKX 模拟盘。
3. 模拟盘跑 2~4 周后，自动生成对比报告：收益曲线、信号一致率、成交价偏差和滑点、手续费、资金费率。
4. 全过程可复现1

## 5. 方案

选 **A：自己写轻量框架，交易所接口用 ccxt**。
- 理由：偏差分析要求完全掌握撮合假设，每个环节都要能在报告里讲清楚；1 小时级不需要高性能引擎。
- 不选 NautilusTrader：学习曲线陡，撮合逻辑在框架内部，报告里难以讲清偏差来源。
- 不选 Freqtrade：它的 dry-run 是在本地模拟成交，不是 OKX 官方模拟盘，对比会变成"两套模拟比来比去"。

## 6. 架构

```
bitcoin/
├─ config/
│   ├─ settings.yaml       品种、频率、费率、风控参数（入 git）
│   └─ .env                OKX 密钥（不入 git）
├─ bitquant/               主包
│   ├─ models.py           数据结构：K线、订单、成交、持仓
│   ├─ data/               历史 K 线和资金费率的下载、本地存储（Parquet）
│   ├─ exchange/           对 ccxt 的封装：行情、账户、下单、模拟盘开关
│   ├─ strategy/           策略接口 + 具体策略
│   ├─ broker/             执行器接口 + 回测执行器 + OKX 执行器
│   ├─ runner/             回测驱动、模拟盘驱动
│   ├─ journal.py          统一的交易日志（回测和模拟盘用同一种格式）
│   ├─ risk.py             风控检查
│   ├─ compare.py          回测与模拟盘的对比计算
│   ├─ alert.py            邮件告警
│   └─ api/                网站后端（FastAPI：只读接口 + 回测任务）
├─ web/                    网站页面（纯 HTML/CSS/JS）
├─ scripts/                命令行入口
├─ deploy/                 服务器部署脚本、systemd 服务文件
├─ tests/
├─ data/                   本地数据（不入 git）
└─ docs/                   设计文档、计划
```

数据流：

```
回测：  历史数据 ──> 回测驱动 ──> 策略 ──> 回测执行器 ──> 交易日志A
模拟盘：每小时收线 ──> 模拟盘驱动 ──> 策略 ──> OKX执行器 ──> 交易日志B
                                     (同一份代码)
对比：  交易日志A + 交易日志B ──> 对比报告
```

要点：
- 策略不知道自己跑在回测里还是模拟盘里，只认"给我截至现在的 K 线，我返回目标仓位"（见 7.1）。
- 本地电脑和服务器用同一个代码仓库；服务器上运行交易进程（模拟盘驱动）和网站进程。
- 包名用 `bitquant`，避免和 PyPI 上已有的 `bitcoin` 包重名。

模块对应的阶段：阶段 1 = models / data / exchange / broker/okx；阶段 2 = strategy / risk；阶段 3 = broker/backtest / runner / journal / compare / alert / deploy；阶段 4 = api / web。

## 7. 详细设计

### 7.1 核心接口（10-12 确认）

处理链：K线 → 策略 → 目标仓位 → 风控 → 下单计划 → 执行器 → 成交 → 交易日志。回测和模拟盘只有「K 线来源」和「执行器」两处不同，其余是同一份代码，偏差可以干净地归因。

| 模块 | 接口 | 要点 |
|---|---|---|
| 策略 | `targets(bars: dict[str, DataFrame]) -> DataFrame` | 输出目标仓位（仓位市值 ÷ 分配资金，负数为做空）；无状态；声明 `warmup`（指标所需的最少 K 线数），回测从 warmup 之后才开始交易；必须通过因果性测试；回测对全部历史调用一次，模拟盘每小时追加新 K 线后再调用、取最后一行；支持多品种（可做期现套利） |
| 风控 | `apply_risk(targets) -> targets` | 现货 0~1；永续 -3~3；总敞口上限；资金占用（现货市值 + 永续保证金）≤ 分配资金；单日亏损熔断（默认 5%） |
| 下单计划 | `plan_orders(targets, positions, prices, rules) -> list[Order]` | 按最小下单量和精度取整；变化太小的不调；交易规则从 OKX 取一次存成文件，回测共用 |
| 执行器 | `positions()`、`execute(orders) -> list[Fill]` | 回测：按下一根开盘价加滑点成交，扣手续费、收付资金费；OKX：用 ccxt 下市价单，取回真实均价和手续费；模拟盘和实盘由一个开关切换 |

统一约定：
- 时间用 UTC；K 线按收盘时间标记（标为 13:00 的 K 线覆盖 12:00–13:00）。
- 数量用币的数量；永续合约的张数换算只在 OKX 执行器内部做。
- 仓位按配置里的分配资金（如 10000 USDT）计算，不用账户总权益；分配资金是固定金额，不随盈亏滚动复利，方便回测和模拟盘对比。
- 订单编号 = 策略 + 品种 + 信号时间：回测和模拟盘一一配对，重启后能防止重复下单。

### 7.2 阶段 1：OKX 连接与数据（10-12 确认）

10-12 实测：OKX 资金费率接口只能拉最近约 3 个半月（最早到 2026-06-29）。更早的数据通过官网历史数据接口 `/api/v5/public/market-data-history`（module=3）自动下载 2022-03 起的月度 CSV，单次查询的时间跨度不能超过 10 个月；文件和接口重叠部分的数值完全一致。2022-03 的现货、永续 1 小时 K 线都能从接口拉到（每页最多 300 根）。历史上有过非整点结算（2022-12-18 18:54、2022-12-29 08:00:01），回测按实际结算时间收付。所以回测统一从 **2022-03-01** 开始。

| 模块 | 内容 |
|---|---|
| `exchange/okx.py` | 两个连接：「行情连接」走真实市场，不开模拟盘开关、不用密钥；「交易连接」只负责下单和查账户（理由见 7.4）。ccxt 4.5.85，demo 模式自动加模拟盘请求头；密钥按模式分开读（`OKX_DEMO_*` / `OKX_LIVE_*`），本期 live 模式拒绝启动；交易规则快照存 `data/market_rules.json` |
| `data/` 历史 | K 线增量下载、断点续传（ccxt 自动切换近期/历史接口）；资金费率近 3 个月走接口，更早的由脚本自动下载官网月度文件（CSV 列：instrument_name, funding_rate, funding_time）；每个品种一个 Parquet，先写临时文件再改名；检查缺失、重复、价格异常，缺口只记录不补 |
| `data/` 实时 | 整点过 5 秒拉最近几根，丢掉还没收盘的那根；没出来就重试，最多等 1 分钟，否则跳过并记日志；资金费率结算后追加 |
| `scripts/init_demo_account.py` | 账户切到合约模式、单向持仓，两个永续逐仓 3 倍；把赠送的 BTC/ETH 换成 USDT，让交易所持仓 = 策略持仓 |
| `scripts/okx_smoke.py` | 查余额和持仓；各品种用最小数量下市价单；限价单挂单再撤单；按自定义订单编号（只含字母数字，≤32 位）查询 |

配置示例（`config/settings.yaml`）：

```yaml
exchange:
  mode: demo                 # demo / live（live 本期禁用）
  proxy: null                # 需要代理时填写，如 http://127.0.0.1:7890
symbols:
  spot: [BTC/USDT, ETH/USDT]
  swap: [BTC/USDT:USDT, ETH/USDT:USDT]
timeframe: 1h
history_start: 2022-03-01
capital_usdt: 10000
```

验收：① 4 个品种从 2022-03-01 至今的 1 小时 K 线和资金费率全部入库，数据质量报告里的缺口都能解释；② 增量更新重复运行，数据不变也不重复；③ 拿到模拟盘密钥后，`okx_smoke.py` 全部通过。没有密钥可以先做连接、历史数据和实时更新。

### 7.3 展示网站（10-12 确认）

```
服务器（nginx + 两个独立进程）：
  交易进程（常驻，每小时）──写──> 交易日志（SQLite）、行情（Parquet）
                                          │ 只读
  浏览器 ──> nginx ──┬─ /       页面文件 web/（HTML/CSS/JS）
                     └─ /api/*  ──> 网站进程（FastAPI，只监听本机）
                                          └─ 发起回测 ──> 回测子进程（同时只跑 1 个）
```

- 交易和网站是两个进程：网站出错、被刷、回测占满 CPU，都不影响下单；systemd 给网站进程设内存上限，内存紧张时被杀的是网站。
- 网站进程不加载 OKX 密钥，没有下单、改仓位、改配置的接口，对交易数据只读。
- 网页发起回测：需要口令（浏览不需要）；参数有白名单和范围检查；同时只跑 1 个，其余排队；单次超时 2 分钟；相同参数直接返回缓存结果；在子进程里跑，跑完释放内存。
- 前端是纯 HTML/CSS/JS 文件，用 fetch 调 `/api`；nginx 负责托管页面、转发 `/api`、开 gzip，以后的 HTTPS 也在这里配。
- 内存估算（2GiB + 2G 交换）：系统和 nginx 约 350MB，交易进程约 250MB，网站进程约 150MB，回测子进程约 400MB，合计约 1.2GB。

| 接口 | 内容 |
|---|---|
| `GET /api/summary` | 净值、关键指标、当前持仓 |
| `GET /api/equity` | 净值曲线（模拟盘或回测，时间跨度长时自动降采样） |
| `GET /api/trades` | 成交记录 |
| `GET /api/candles` | K 线和买卖点 |
| `GET /api/compare` | 回测与模拟盘的对比 |
| `GET /api/status` | 交易进程心跳、最近的错误 |
| `POST /api/backtests` | 发起回测（需要口令），返回任务编号 |
| `GET /api/backtests/{id}` | 查询回测进度和结果 |

页面：总览、回测 vs 模拟盘、行情与买卖点、策略说明、运行状态、回测实验室。

UI 迭代流程：先在本地用回测数据跑 `uvicorn --reload`，我改页面，用户刷新浏览器看效果，按喜好实时调整；风格方向先请用户给参考样例，或从几种风格里挑（偏简洁克制）；定稿后部署到服务器，接入真实的模拟盘数据。

### 7.4 回测与对比（10-12 确认）

10-12 实测：OKX 模拟盘是一个独立的市场。买一价、卖一价和真实市场一致，但最新成交价、K 线、成交量、资金费率都是模拟盘自己的（同两次结算的资金费率：真实市场 +0.0025%、−0.0011%，模拟盘 +0.0016%、+0.0026%）。因此：
- 行情一律走真实市场的「行情连接」；下单和查账户走「交易连接」。
- 资金费在对比报告里单独核算，并给出"换成真实资金费率重算"的模拟盘收益。资金费率套利类策略在模拟盘上的收益不能代表真实情况，报告里要注明。

回测成交假设：

| 项 | 假设 |
|---|---|
| 成交时机 | 信号 K 线收盘后，按下一根 K 线开盘价成交 |
| 滑点 | 每边 0.02%，可配置；模拟盘跑完后用实测值校准 |
| 手续费 | 吃单费率：现货 0.10%，永续 0.05%（OKX 普通用户，可配置，以官网为准） |
| 资金费 | 用真实历史费率在结算时刻收付；仓位价值用当时收盘价近似 |
| 强平 | 用每小时最高/最低价检查是否触及近似强平价 |
| 部分成交与冲击 | 不考虑（1 万 USDT 规模） |
| 资金占用 | 现货市值 + 永续保证金 ≤ 分配资金，超出由风控按比例缩减 |

交易日志（SQLite，回测和模拟盘同一套表）：

| 表 | 记录内容 |
|---|---|
| runs | 类型（回测/模拟盘）、策略和参数、配置指纹、代码版本、数据区间 |
| signals | 每小时每个品种的目标仓位（风控前、风控后） |
| orders | 订单编号、信号时间、方向、数量、决策价、到达价 |
| fills | 成交均价、数量、手续费、时间 |
| funding | 结算时间、持仓、费率、金额 |
| equity | 每小时权益快照 |
| events | 跳过的小时、重试、报错 |

- 决策价 = 回测假设的成交价（下一根开盘价）；到达价 = 下单前一刻真实市场的对手价（买单取卖一，卖单取买一）。
- 交易进程写 `journal.db`，网页发起的回测写 `backtests.db`，结构相同；交易日志只有交易进程会写。

对比实验：模拟盘跑完后做"影子回测"，即用同一段真实行情、同样的参数和起始资金重跑回测，两边按订单编号配对。

| 指标 | 算法 |
|---|---|
| 信号一致率 | 同一小时两边目标仓位是否相同（理论上应为 100%） |
| 成交价偏差 | 延迟偏差 = 到达价 − 决策价；执行偏差 = 成交价 − 到达价（基点，对我们不利记为正） |
| 手续费 | 实际费率 vs 假设费率 |
| 资金费 | 模拟盘实际收付 vs 按真实费率计算 |
| 收益差拆解 | 总收益差 = 滑点 + 手续费差 + 资金费差 + 错过或多出的交易 + 剩余部分 |

- 校准闭环：用实测的滑点和费率更新回测假设后重跑，展示收益差缩小多少。
- 样本量：实验参数要保证 4 个品种合计每天至少 2~3 笔交易（阶段 2 选参数时考虑）。
- 对比计算放在 `bitquant/compare.py`，网站和课程报告脚本共用。

### 7.5 部署、错误处理与测试（10-12 确认）

部署（阿里云香港或海外地域）：

| 项 | 做法 |
|---|---|
| 系统 | Ubuntu 24.04（自带 Python 3.12，代码按 3.11 以上的语法写）；2G 交换空间；开启时间同步 |
| 代码与依赖 | 从 GitHub 私有仓库拉到 `/opt/bitquant`；`requirements.txt` 锁定版本；服务器用 venv，不装 conda |
| 运行用户 | 交易进程用 `trader`，网站进程用 `web`，都不是 root。OKX 密钥文件只有 `trader` 能读，网站从文件权限上就读不到；回测口令放在网站自己的配置里；邮件发信配置放在交易一侧 |
| 进程守护 | systemd 管理两个服务，崩溃自动重启、开机自启；网站服务内存上限 800MB（包括回测子进程），内存紧张时优先关掉网站 |
| 网络 | 安全组只开 22、80、443；FastAPI 只监听本机；SSH 只允许密钥登录；OKX 密钥绑定服务器公网 IP 和本机出口 IP |
| 更新 | 本地推到 GitHub，服务器运行 `deploy/deploy.sh`：拉代码、装依赖、跑测试，测试通过才重启 |
| HTTPS | 先用 IP + HTTP（此时回测口令是明文传输）；有域名后用 certbot 申请免费证书 |

错误处理（原则：宁可漏跑一轮，也不能下错单）：

| 情况 | 处理 |
|---|---|
| 网络错误、被限流 | ccxt 自带限速；失败后分别等 1、2、4 秒重试，最多 3 次 |
| 某一步出错 | 记入 events 表，这一轮放弃，下一小时照常运行 |
| 下单后没收到回应 | 先按订单编号查：查到了算成功；查不到再用同一个编号重发，交易所会拒绝重复编号 |
| 程序重启 | 撤掉遗留挂单 → 读 OKX 实际持仓 → 和日志里最后一轮的目标比对，不一致就记事件 → 照常进入下一轮（目标仓位设计会自动调回） |
| 停机漏跑 | 不补下过去的单，只按最新信号调仓；漏掉的小时记为"漏跑" |
| 单日亏损熔断 | 当天（UTC）亏损达到分配资金的 5% 就全部平仓，当天不再开仓（可配置） |
| 心跳与告警 | 交易进程每轮写心跳；systemd 定时器每 15 分钟检查一次，超过 2 小时没心跳就告警；连续 3 轮出错、熔断触发时也告警。告警用**邮件**：QQ 或 163 邮箱的 SMTP 发信，Python 自带 smtplib，不加依赖 |

测试：

| 测试类型 | 内容 | 什么时候跑 |
|---|---|---|
| 单元测试 | 下单计划（取整、最小下单量、小变化不调）；风控（上下限、熔断）；回测执行器（手工构造的 K 线，和手算的手续费、资金费、强平结果对照）；数据层（丢掉未收盘 K 线、检测缺口、增量合并不重复）；订单编号格式；网站接口（口令、参数范围） | 每次改动 |
| 因果性测试 | 每个策略都自动跑：截断在任意时刻，结果必须和用全部数据算的一致 | 每次改动 |
| 一致性测试 | 同一段历史数据走两条路径：回测驱动；模拟盘驱动配一个按回测规则成交的假执行器，逐小时喂数据。两份交易日志必须完全相同 | 每次改动 |
| 录制回放 | 把 OKX 真实返回存成 JSON 样本，测试读样本，不联网、不需要密钥 | 每次改动 |
| 联网测试 | 连通性检查、`okx_smoke.py` | 手动运行 |

写法：每个模块先写测试，再写实现。版本管理：开始写代码时初始化 git，本文档作为第一个提交；是否推到 GitHub 私有仓库届时确认。

## 9. 安全与合规

- OKX API 密钥只开"读取 + 交易"，**绝不开提现**；绑定 IP 白名单（服务器公网 IP + 本机出口 IP）。
- 模拟盘和实盘的密钥分开，模拟盘密钥在 OKX 的"模拟交易"页面单独创建。
- `.env` 和 `data/` 不入 git。
- 网站进程不加载 OKX 密钥，也没有下单或改配置的接口；服务器上交易和网站分属两个用户，网站从文件权限上就读不到密钥（见 7.5）。
- 网页发起回测需要口令，口令和 OKX 密钥分开存放。
- 服务器 SSH 只允许密钥登录；安全组只开 22、80、443。
- 只用于个人研究；不对外提供信号或带单服务。
